# Generation trajectory protocol

Use the [module README](../generation_trajectory/README.md) for the current CLI, small CPU example, checkpoint reuse, and output formats.

The paper visualization uses circular source samples and four target distributions: two moons, checkerboard, letter F, and letter M. The DFM columns use 1 and 20 function evaluations. The retained Flow Matching and MeanFlow baselines allow comparison using the same synthetic data construction.

## Compare step budgets

1. Fix dataset, model architecture, training budget, and seed.
2. Train once and save the checkpoint plus resolved configuration.
3. Reuse that checkpoint and the same initial source samples at each NFE.
4. Export the actual model-evaluated sample states and their times.
5. Plot those states with consistent axes and point selection. A drawn line between sampled states is a visualization, not evidence of intermediate model evaluations.

A small demo or smoke run checks the workflow and does not reproduce a paper figure. Use larger documented settings for a scientific comparison and retain its outputs. Original paper checkpoints and matching run manifests are not included; the webpage figures are archived manuscript assets, not outputs generated by the default public command.

## Reference paths

Training interpolants, independent endpoint couplings, and model transport trajectories have different meanings. A sampled coupling is not a unique ground-truth generative trajectory. Use precise captions and keep model trajectories distinct from illustrations of the interpolation construction.
